## Response-@intercept verdict (server.py:818-828): CONFIRMED BUG (behavioral, not a crash)
The interceptor keeps `Response.tokens` (`session.py:402-420`). The server then re-parses `raw` through `ChatDialect.parse_response`, which is `response_from_wire` and has no tokens (`chat.py:254-256, 537-538`). `_commit_turn` with `tokens=None` produces empty input nodes plus a `sampled=True` assistant node with `token_ids=mask=logprobs=[]` and the rewritten text (`graph.py:782, 870-911`). The synthetic probe showed four things. The turn-2 tokens `[20,21…]` are lost. Turn 3 cannot bridge (`previous_token_ids=None`). The branch still concatenates exactly: the empty nodes pass tightening, and node4 absorbs the rewritten turn's re-rendered tokens as mask-False context. The next assistant trains normally. Routing replay is unaffected (empty nodes are skipped). The effect: that turn's samples never train, and the node misattributes the rewritten text as "sampled". Nothing marks it as intended. The fix would be to carry `tokens` over from the pre-rewrite response, or to decide explicitly to mask it.

## Ledger items addressed to F

The orchestrator path is `Env._sampling` → `extra_body.cache_salt` (`envs.py:121-125`) → `RunRequest.sampling` → worker `ctx.sampling.wire_args()` flattens it to top level (`types.py:274-284`) → `TrainClient` pops it (`train.py:370`) → `generate(cache_salt=)` → top-level `/generate` body field `body["cache_salt"]` (`renderers/client.py:330-331`), not inside `sampling_params`. The eval path puts it top-level in the chat body (`chat.py:589-597`). E's "top-level" is correct; 06 cites `client.py:330-331`, which is right.

- **B — X-Session-ID == trace id, released by finish_sessions**: CONFIRMED. `session_id=session.trace.id` (`server.py:798`) becomes the `X-Session-ID` header (`train.py:440`, `clients/client.py:16`). - **G — Trace.notify per turn**: CONFIRMED. `record_call` calls `notify()` (`server.py:581`) for every real exchange, success or failure, and `preview()` also notifies (`trace.py:472-477`). Commit itself does not notify.

- **I — hooks injected by param name via invoke**: PARTIAL. Scoring/finalize hooks are injected **by name** (`task`, `trace`, `runtime`). Interception hooks (`@intercept`, `@stop`) are injected **by annotated type** (`Request`/`Response`/`Trace`) via the type-keyed branch of `invoke` (`utils/decorators.py:29-38`; `session.py:67-69`).
- **I — scoring errors → TaskError, not 0**: CONFIRMED (`task.py:222`, `rollout.py:497-509`, `errors.py:76-89`). prime-rl drops the trace (`algo/base.py:35-42`).
- **I — judge default Prime inference, PRIME_API_KEY, missing → "EMPTY"**: CONFIRMED (`configs/judge.py:14-22`, `configs/client.py:29-35, 93-104`). The exception is a taskset reward that wraps the judge in its own try/except, which is I's to check for math_env.
- **C — frozen-source node logprobs**: CONFIRMED. On the renderer path `logprobs=1` is always forced and validated (`renderers/client.py:312`, `:137-188`), so frozen-source nodes carry the **frozen model's** sampled-token logprobs. `GenerationSource.sampling_args` popping `logprobs` (`generation_source.py:43-49`) has no effect there. An engine without logprobs fails every turn.
- **C — is_content population**: CONFIRMED. It comes from renderer attribution only when `len(is_content)==len(prompt_ids)` (`graph.py:784-785`). Input nodes get their slice. The assistant node gets `[False]*gen_prompt + [True]*completion`, which includes reasoning and stop tokens (`graph.py:907-909`). Tokenless (eval) turns get `[]`.
- **H — which process hosts the renderer pool**: CONFIRMED. It is the env-server worker, process-global on the class (`train.py:222-251`).
