- G-open "dead elastic worker detection": CONFIRMED that none exists. Health is answered from a pre-packed broker reply (pool.py:43, 194-197). The broker never checks `is_alive()`. Runs have no timeout on the orchestrator side (client.py:100-102, and nothing in envs.py or dispatcher.py). A worker that crashes at start takes every run routed to it into a permanent hang. A worker that dies mid-run keeps receiving new requests whenever its frozen `active` count is the minimum. Hung train groups are reclaimed only by the stale sweep or an overload cut; eval and frozen-sourced groups hang forever.
- G-open "broker stall at 1000 queued msgs": CONFIRMED by execution. The per-worker DEALER has the default SNDHWM of 1000, and the 1001st `await send_multipart` blocks. The broker awaits that send inline (pool.py:221-223, 234-236), so the whole broker freezes. This can't happen under the default elastic pool (about 115 per worker). It can happen with a static pool or capped `max_workers` once in-flight ≳ 1000·N, and transiently while static workers are still loading.
- G-open "k8s env servers": RESOLVED. The chart has no env-server resource, and only the rl/eval/sft launchers spawn env servers. A k8s run needs externally deployed servers plus `serve.address`.
- G-open NeMo `taskset.config` identity: RESOLVED. It is the same object (env.py:97, 104; taskset.py:43-44).
- G-open config-dir agreement: PARTIAL, left for A. The orchestrator uses `$PRL_ATTEMPT_CONFIG_DIR` (every sbatch exports it); otherwise it uses `<output_dir>/configs/latest/resolved`. Locally, agreement relies on `output_dir == run_dir` (pathing.py:38-72, 158-168).
