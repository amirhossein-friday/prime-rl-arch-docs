## How to use this doc

- **Find by symptom.** Search this page for the config key, error string, metric name, file or port in front of you. Every row names its trigger.
- **Stable IDs:** `B-nn` confirmed bugs, `H-nn` silent correctness hazards, `O-nn` operational traps, `P-nn` performance cliffs, `D-nn` docs-vs-code drift. Link a row as `22-gotchas-and-bugs.md#b-01` (anchors are lowercase). IDs are never renumbered: a later row takes the next free ID and sits in its rank position, so an ID's number is not its rank (e.g. O-56 to O-58).
- **Rank.** Rows in each table are ordered by severity, then by likelihood:
  - **S1**: hit by shipped or default configs; the run breaks, or it trains on something other than you think.
  - **S2**: hit under a plausible non-default config or load.
  - **S3**: edge case, extension-only, or cosmetic.
- **Evidence:**
  - `static`: read in code.
  - `probe`: a reviewer executed it (config validators, `cli()`, CPU/DTensor/pyzmq probes, synthetic traces, an import).
  - `runtime?`: the mechanism is established, but the end-to-end effect needs a GPU or live run to observe.
  - `[UNVERIFIED]`: not confirmed.
- **Cite paths** are relative to the prime-rl root, with these abbreviations:
  - `configs/*.py` = `packages/prime-rl-configs/src/prime_rl/configs/*.py`. TOMLs under `configs/…/*.toml` are the repo's config directory.
  - `utils/validation.py` = `packages/prime-rl-configs/src/prime_rl/utils/validation.py`.
  - `v1/…` = `deps/verifiers/verifiers/v1/…`.
  - `renderers/…` = `deps/renderers/renderers/…`.
  - `cli.py` = `deps/pydantic-config/src/pydantic_config/cli.py`.
  - Any other path is under `src/prime_rl/` unless it starts with `deps/`, `scripts/`, `docs/`, `examples/`, `tests/`, `k8s/` or `skills/`.
- The **Section** column points to the full mechanism. If you just want a run to work, go to [§6 Safe first run](#6-safe-first-run-checklist).

| <a id="h-01"></a>**H-01** | S1 | **Old-weight KV is reused across weight swaps, at three levels** | Every live-policy run, on every transport: the prefix cache is never reset on update.<br>• **Group:** the salt is fixed at group open, members dispatch one at a time, and open groups are continued first. The closed gate and `PREFER_EVAL` also park half-dispatched groups. Members sent after a swap carry the old salt onto the new weights.<br>• **Episode:** the rollout-wide salt is reused on every later turn.<br>• **Request:** `/pause` is `mode="keep", clear_cache=False`, i.e. a freeze; mid-decode requests resume on the new weights over their old KV.<br>• **LoRA:** `/load_lora_adapter` reloads in place with no pause at all. | μ becomes a hybrid (new weights over old-weight KV) that matches no single π_v. `inference_logprobs` come from the forward that actually sampled, so π_θ/μ sees a real, larger \|log r\| (more IPO/IcePop masking, higher `mismatch_kl`), not a silent bias. `PolicySpan.start` still names the old version, so staleness is over-counted: conservative, and the M bound still holds.
